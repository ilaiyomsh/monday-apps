## 3. מלכודות שעלו דם — אל תבזבז עליהן סשן שני

כולן תועדו ב-`.claude/skills/mapps/references/cli.md` (PR #628). התמצית:

1. **`code:logs` — אין דרך עובדת לקרוא לוגים מהעבר.** `-f`/`-e`/`-r` עם
   `-s live` מפילים את הפקודה ב-**exit 1 בלי להדפיס כלום**; עם
   `-s History` מתעלמים מהם בשקט; ו-`-s History` לבדו לא מחזיר אירועים
   לעולם. הצורה היחידה שעובדת: tail חי בלי פילטרים, שרץ **לפני** האירוע.
2. **סטרים חי נסגר אחרי בדיוק 10 דקות** ("Closed connection.", exit 0).
3. **סטרימים מקבילים מחלקים ביניהם אירועים — לא משכפלים.** ארבעה
   סטרימים על אותה גרסה, **בדיוק אחד** קיבל את ה-POST של ה-cron. ריבוי
   סטרימים כ"יתירות" **מזיק**. הרץ אחד לכל (גרסה, סוג).
4. **`code:logs` מרנדר רק את `message`** ומשמיט כל מפתח JSON אחר. לכן
   `durationMs` של 0.14.0 היה בלתי קריא בפרודקשן. ערכים שצריך לקרוא —
   לקפל לתוך ההודעה, כמו ש-`api_latency` עושה.
5. **`scheduler:run` לא מחזיר את גוף התשובה** — רק
   "Successfully triggered job".
6. **`latency` בלוג ה-http הוא מילישניות.**

**מזהי גרסאות (נכון להיום):** app `11704868` · draft v6 `16380275` ·
live v5 `16194490`. אלה **version ids** — `code:logs -i` דורש אותם, לא את

**כפתור הרצה ידנית של הפעולה המתוזמנת — צד שרת בלבד.**

- טסטים: `tests/scheduled-run.test.js` (10), `tests/admin-api-run-scheduled.test.js` (5).
  **4 מוטציות הומתו**, שני המודולים DONE בשער.

**החלטת בעלים שקובעת את ההתנהגות:** הכפתור **שולח לכולם מחדש, תמיד**
(`skipAlreadySent: false`). שתי תוצאות שנבדקות בטסטים ואסור לשבור:
- אף אחד לא מדולג → לחיצה כפולה שולחת פעמיים;
- הסימון הפר-סלוטי נכתב **רק** תחת הדגל הזה (`digest-run.js:203`), ולכן
  ריצה ידנית **לא משאירה סימון** ולא משתיקה את ה-cron שאחריה. ריצה ידנית
  ב-09:00 + cron ב-10:00 = הנמען מקבל **פעמיים**. זו תוצאה מכוונת של
  הבקשה, והבעלים יודע עליה.

**כלל שנעקף במכוון:** `scheduler-summary-file.test.js` נועל
"קובץ נוצר בריצת cron בלבד". הכלל **נשאר בתוקף** ל-`/api/digest/send`
ו-`resend-today`, והטסט לא נגע — הראוט החדש נפרד. הבעלים ביקש כפתור
שמריץ את הפעולה המתוזמנת כולל הדוח שלה, לא שהכפתורים הקיימים ישנו התנהגות.

## 5. מה נשאר — חמש משימות, עם ההחלטות שכבר התקבלו

### A. UI לכפתור ההרצה הידנית  ← הכי קרוב לסיום
הצד שרת גמור ונבדק. נשאר רק הקליינט:
- `src/client/admin/types.ts` — טיפוס תשובה (יש `DigestSendResponse` להסתמך עליו; הוסף `durationMs`, `reportSent`).
- `src/client/admin/components/DigestSection.tsx` — הסקשן
  "תצוגה מקדימה ושליחה" (סביב שורה 320) כבר מחזיק "שליחה עכשיו" עם
  שלב אישור דו-שלבי. הוסף שם כפתור שני באותו דפוס, שקורא
  `/api/digest/run-scheduled` ומציג גם את `durationMs` ו-`reportSent`.
- **נסח את ההבדל למשתמש**: "שליחה עכשיו" שולחת את המייל; "הרצת הפעולה
  המתוזמנת" שולחת **וגם מפיקה את דוח ה-CSV**.

### B. בלוקים באקורדיון, מכווצים כברירת מחדל
`components/DigestBlocksSection.tsx`. הבקשה: "כל בלוק יוכל להיות מצומצם
בתצוגת אקורדיון **בברירת מחדל**, כדי שהמשתמש יקבל מסך נקי".
שים לב: זו גם הסיבה שהמשתמש לא מצא את כפתור השליחה — הוא קבור מתחת
לעורך הבלוקים. כיווץ ברירת מחדל פותר את שתי הבעיות.

### C. §7.4 — השלמת שעה שהוחמצה  (אושר במפורש)
`src/routes/scheduler.js`, מסנן השעה סביב שורה 56 (`sendHour !== hour`).
היום ההשוואה היא לשעה **שלמה**, ופעימה שמתעכבת וחוצה גבול שעה מפספסת את
הטננט לאותו יום. עם הסימון הפר-סלוטי אפשר להשלים בבטחה: פעימה תשלים למי
שטרם קיבל **באותו slot**. אל תשבור את הקפאת השעון (`now: () => clock`) —
היא מה שמונע חתימה על שני סלוטים.

### D. עמודת סטטוס נפרדת ב-CSV  (אושר במפורש)
`src/helpers/digest-summary-report.js`. היום העמודה האחרונה ("שגיאה")
נושאת גם סיבות שאינן שגיאות ("כבר נשלח בסלוט הזה", "אין משימות פתוחות").
הפרד ל-outcome (נשלח / דולג / נכשל) + טקסט חופשי, כדי שאפשר יהיה לסנן
כשלי SMTP אמיתיים באקסל. שים לב: `kind` לא מוכר **זורק**
(`unknown_summary_row_kind`) במכוון — שמור על זה.

### E. שער לייבל בלוח המשתמשים  ← הגדולה, ובנה אותה יחד עם D
הבקשה: מיפוי **עמודת סטטוס בלוח המשתמשים + לייבל מסוים**, כך שרק משתמשים
שמסומן להם הלייבל הזה יקבלו מייל — כיבוי קל פר משתמש.

נוגע ב: סכמת הקונפיג (`admin-api.js` ולידציה), בחירת הנמענים
(`services/digest-service.js`), מסך האדמין, ודוח ה-CSV.

**החלטה שכבר התקבלה ונאמרה לבעלים:** כשהעמודה או הלייבל **לא מוגדרים** —
**כולם מקבלים**, כמו היום. ברירת מחדל הפוכה הייתה משתיקה את המייל אצל כל
הטננטים הקיימים ברגע השדרוג, בלי שאיש נגע בהגדרה.

**הכריכה עם D:** מי שנחסם בשער חייב שורה משלו ב-CSV עם סיבה
("לא מסומן לקבלת מייל"). אחרת הקובץ מתיימר לכסות את כל העובדים בזמן שהוא
שותק על אנשים — וזו בדיוק הטענה היחידה שהקובץ קיים בשבילה (§5.2).

## 6. תהליך — מה יעצור אותך אם תתעלם

- **test-guard הוא שער פיזי.** כל מודול מקור שנגעת בו חייב verdict DONE
  או ויתור, אחרת ה-Stop hook חוסם את סיום הסשן. הזרימה שעבדה:
  ```bash
  cd apps/deadline-confirm
  RG=../../.claude/skills/test-guard/scripts/redgreen.sh
  $RG spotcheck-arm  src/<file>.js tests/<file>.test.js
  # ← החל מוטציה סמנטית אחת עם Edit
  $RG spotcheck-fire src/<file>.js tests/<file>.test.js 'תיאור המוטציה'
  # חזור עד ≥2 KILLED, ואז:
  $RG verdict tests/<file>.test.js   # → DONE
  ```
  `green` לבדו ייכשל בלי `red` קודם — לקוד קיים השתמש ב-spotcheck.
- **אל תדחוף ל-main.** שחרור עובר PR מ-develop, ובריפו הזה הפרקטיקה
  בפועל היא **שחרור סלקטיבי** (קומיט אחד שמעלה אפליקציה אחת) — ראה
  `monday-cicd` Mode 5. שחרור מלא היום היה 904 קומיטים ו-9 אפליקציות.
- **`git push` ומיזוג לפרודקשן — שאלה מאשרת אחת כל אחד.** `git commit`
  אוטונומי.
- **`axis-sync-calender` נכשל בכל שחרור live** כי אין לו גרסת live
  מלכתחילה. זה שומר שעובד נכון, לא רגרסיה — אל "תתקן" אותו.

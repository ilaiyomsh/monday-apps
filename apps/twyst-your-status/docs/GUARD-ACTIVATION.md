# הפעלת השומר (Guard) — צעדי בעלים, פעם אחת

הרכיב: שרת monday-code של **אותה אפליקציה** (twyst-your-status, App ID 11775054),
שמאמת כל שינוי בעמודה מנוהלת מול הכללים ומחזיר שינוי לא חוקי תוך שניות —
כולל שינויים שנעשו בחלון הטעינה הקרה, במובייל, בקנבן וב-API. רקע והחלטה:
`BYPASS-PROOF-DECISION.md` (הוחלט: שכבת שומר בלבד, ללא נעילת עמודה — הייחוס
ביומן הפעילות נשמר; רק ביטול שינוי פסול נכתב על שם זהות-השירות).

הודעת הביטול למשתמש (נוסח הבעלים, קבוע בקוד):
**"השינוי שבוצע בוטל - מכיוון שאינו עומד בהגדרות העמודה"**

## מה נאכף

לכל שינוי בעמודה, מכל מקור, הסדר: (1) המשנה הוא זהות-השירות? דלג (loop guard).
(2) אין כללים שמורים לעמודה? דלג. (3) אימות מול **אותם מודולי כללים של הבורר**
(מקור אמת אחד, מוטמע ב-bundle): לייבל מוסתר, הרשאות משתמש/צוות, שער עמודת
אנשים, חוקי מעברים כולל מצב ריק (זהות ריק≡5), ו**שדות חובה** — נקראים מהפריט
עצמו ונשפטים לפי אותו רגיסטרי (checkbox לא מסומן = ריק, סטטוס 0 = מלא וכו').
(4) שינוי פסול: קריאה חוזרת של התא (הגנת staleness) → החזרה לערך הקודם →
notification למבצע. כשל קריאה שלנו לעולם לא מחזיר שינוי (fail-soft, מתועד בלוג).

## צעדי הפעלה (בסדר הזה)

1. **סקופים** — Developer Center → App → גרסת draft → Permissions: להוסיף
   `webhooks:write`, `notifications:write`, `account:read` (הקיימים:
   boards:read/write, users:read, teams:read). לאשר מחדש התקנות קיימות.
2. **סוד ל-GitHub (חד-פעמי)** — `TWYST_GUARD_URL` (כתובת השרת, ראה צעד 4):
   `gh secret set TWYST_GUARD_URL --repo ilaiyomsh/monday-apps` — מוזרק לבניית
   ה-client כ-`VITE_TWYST_GUARD_URL`. בהיעדרו ה-client פשוט לא מנסה להירשם.
3. **משתני סביבה לשרת** — אחרי הפריסה הראשונה (merge ל-develop מריץ את
   `deploy-draft-twyst-guard`):
   ```bash
   mapps code:env -i 11775054   # אינטראקטיבי, או -k/-v:
   #  MONDAY_CLIENT_ID     — Developer Center → App → Basic Information
   #  MONDAY_CLIENT_SECRET — שם (Client Secret; משמש גם לאימות sessionToken)
   #  MONDAY_SIGNING_SECRET— שם (Signing Secret; אימות JWT של משלוחי webhook)
   #  BASE_URL             — כתובת השרת מ-mapps code:status -i 11775054
   ```
4. **כתובת השרת** — `mapps code:status -i 11775054` אחרי הפריסה; זו הכתובת
   ל-`BASE_URL` (צעד 3) ול-`TWYST_GUARD_URL` (צעד 2).
5. **OAuth Redirect** — Developer Center → App → OAuth → Redirect URLs: להוסיף
   `<BASE_URL>/oauth/callback`.
6. **הפעלה לחשבון** — לפתוח `<BASE_URL>/oauth/start?st=<sessionToken>` (הכפתור
   במסך ההגדרות יופיע בסבב עתידי; עד אז — ידנית מהדפדפן כשמחוברים ל-monday,
   או דרך הבורר של הבעלים). המשתמש שמאשר הוא **זהות-השירות**: ההחזרות ייכתבו
   בשמו. מומלץ משתמש ייעודי בשם ברור (למשל "Twyst Guard").
7. **רישום עמודות** — מרגע ההפעלה, כל שמירת הגדרות של עמודה רושמת אותה
   אוטומטית (idempotent). לעמודות קיימות: להיכנס להגדרות ולשמור פעם אחת.

## גבולות ידועים (מוצהרים)

- תיקון, לא מניעה: הערך הפסול גלוי עד ההחזרה (שניות).
- שרת מושבת = אין אכיפה (fail-open); הבורר ממשיך לעבוד כרגיל.
- ערך שנקבע ביצירת פריט (טופס/שכפול/ייבוא) לא מייצר אירוע שינוי — מחוץ
  להיקף v1 (הוחלט: הבעיה שנפתרת היא חלון הטעינה).
- Axiom ל-guard: לא מחובר ב-v1; הלוגים ב-`mapps code:logs -i 11775054`.

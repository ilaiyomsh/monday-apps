B-001 Tab resets to "פרויקטים" when projects load
HIGH

File: src/components/EventModal/EventModal.jsx

Problem: When creating a new event and clicking the "שוטף" tab while projects are loading, the tab jumps back to "פרויקטים" when the project list finishes.

Root Cause: The modal init useEffect depends on localProjects. When the projects list updates, it re-runs and resets selectedTab.

Solution: Split the modal init useEffect into two separate effects—one for creation mode (no dependency on localProjects) and one for edit/convert mode (with guarded initialization).

// OLD: Single useEffect with localProjects dependency useEffect(() => { if (isOpen && !isEditMode) { setSelectedTab('פרויקטים'); // ← Runs again when localProjects updates } }, [isOpen, isEditMode, localProjects]); // ← Problem: localProjects causes re-run // NEW: Two separate effects useEffect(() => { if (isOpen && !isEditMode && !isConvertMode && !editInitializedRef.current) { setSelectedTab('פרויקטים'); } }, [isOpen, isEditMode, isConvertMode]); // ← No localProjects dependency useEffect(() => { if (isEditMode && !editInitializedRef.current) { editInitializedRef.current = true; // Resolve project with data from eventToEdit } }, [isEditMode]);

B-002 Confetti closes newly-opened modal
HIGH

File: src/hooks/useAllDayEvents.js:99

Problem: When saving an all-day event that triggers confetti and immediately opening another event modal, the confetti callback closes the newly-opened modal instead of the submitted one.

Root Cause: handleCreateAllDayEvent calls modals.closeAllDayModal() both inside AllDayEventModal.handleCreate() (synchronously) and again after the API call (asynchronously). The second call closes any newly-opened modal.

Solution: Remove the redundant close call after the API response.

// OLD (useAllDayEvents.js:99) const onCreate = async (eventData) => { modals.closeAllDayModal(); // ← Already closed in EventModal.handleCreate() const created = await api.createAllDayEvent(eventData); modals.closeAllDayModal(); // ← PROBLEM: Closes new modal! }; // NEW: Remove second call const onCreate = async (eventData) => { modals.closeAllDayModal(); // ← Keep this one const created = await api.createAllDayEvent(eventData); // Remove: modals.closeAllDayModal(); };

B-005 False "unsaved changes?" popup
MEDIUM

File: src/components/EventModal/EventModal.jsx + src/hooks/useEventModals.js:75

Problem: Opening an existing event modal or clicking X without making any edits still shows "Do you want to save your changes?" popup.

Root Cause: selectedItem started as null before the data loader populated it. The hasUnsavedChanges check detected null !== eventToEdit.projectId = true, falsely indicating a change.

Solution: Initialize selectedItem directly from the event's projectId instead of starting as null.

// OLD (useEventModals.js:75) const openEventModalForEdit = useCallback((event) => { setSelectedItem(null); // ← Causes null !== projectId mismatch! setEventToEdit(event); }, []); // NEW: Initialize from event immediately const openEventModalForEdit = useCallback((event) => { setSelectedItem(event?.projectId ?? null); // ← No null mismatch setEventToEdit(event); }, []);

B-006 Timed event dragged into all-day area after resize
HIGH

File: src/hooks/useCalendarHandlers.js (guard at line 96) + resize handler

Problem: After resizing a timed event, dragging it can drop it into the all-day area, which should be prevented by an existing guard.

Root Cause: react-big-calendar determines drop zone by calling getBoundingClientRect() on the drop target. After resize completes, the DOM layout is in CSS transition. When drag starts before layout stabilizes, coordinates are stale, causing incorrect zone detection.

Solution: Add 150ms debounce after resize to allow DOM layout to stabilize before allowing drag.

// In component with resize handler const [isResizing, setIsResizing] = useState(false); const handleResizeStop = () => { setIsResizing(true); setTimeout(() => setIsResizing(false), 150); // Allow 150ms for layout }; // In drag handler (useCalendarHandlers.js) const handleSelectEvent = (event) => { if (isResizing) return; // Block drag during resize window // ... rest of drag logic };

# DEEPLINK — קישור ישיר ליום היעדרות בתוך Day-off

מסמך זה מסביר לאפליקציית-מקור **חיצונית** כיצד לבנות קישור (Deep Link) שפותח את אפליקציית
Day-off
על יום היעדרות מסוים, ומציג את אותה תיבת פרטים שהמשתמש רואה כשהוא לוחץ על יום בלוח-השנה בטאב "ההיעדרויות שלי".

---

## 1. מה צריך כדי לבנות קישור

שני נתונים בלבד:

| נתון | תיאור | דוגמה |
|------|--------|--------|
| `baseUrl` | כתובת ה-Custom Object של מופע ה-Day-off ב-monday | `https://yomsheni-il.monday.com/custom_objects/18417140187` |
| `itemId` | מזהה ה-`item` של יום ההיעדרות בלוח ה-monday | `1234567890` |

ה-`itemId`
הוא אותו מזהה פריט (item) שמייצג את הבקשה בלוח ההיעדרויות. זהו אותו מזהה שמופיע ב-API של monday עבור הפריט.

> **ה-`baseUrl` אינו קבוע.** הכתובת משתנה בין מופע למופע של
> Day-off
> (חשבון/אובייקט שונה → מזהה
> `custom_objects`
> שונה). הדוגמה כאן היא להמחשה בלבד. אפליקציית-המקור שמחוללת את הקישור מקבלת/מחזיקה את ה-`baseUrl`
> הרלוונטי למופע, ובונה ממנו את הקישור — אין להטמיע את הכתובת לדוגמה כקבוע בקוד.

---

## 2. פורמט הקישור

```
{baseUrl}?app[itemId]={itemId}
```

דוגמה מלאה:

```
https://yomsheni-il.monday.com/custom_objects/18417140187?app[itemId]=1234567890
```

### ⚠️ הפרמטר חייב להיות תחת ה-namespace בשם `app[...]`

monday
חושפת לאפליקציה המוטמעת (iframe) **רק** פרמטרים שעטופים בתחילית
`app[...]`.
פרמטר רגיל כמו `?itemId=123`
**יסונן** ולא יגיע לאפליקציה.

| נכון ✅ | שגוי ❌ |
|---------|---------|
| `?app[itemId]=1234567890` | `?itemId=1234567890` |

האפליקציה קוראת את הערך דרך
`monday.get('location')`,
ש-monday
מחזירה ממנו את הפרמטר ללא ה-namespace:

```jsonc
{
  "data": {
    "href":   "https://yomsheni-il.monday.com/custom_objects/18417140187",
    "search": "app[itemId]=1234567890",
    "query":  { "itemId": "1234567890" }
  }
}
```

## 3. כיצד לבנות את הקישור בקוד

### JavaScript / TypeScript

```ts
function buildDayOffDeepLink(baseUrl: string, itemId: string | number): string {
  const url = new URL(baseUrl);
  // השם המלא של הפרמטר הוא "app[itemId]" — monday מסירה את עטיפת app[] בצד הלקוח.
  url.searchParams.set('app[itemId]', String(itemId));
  return url.toString();
}

// שימוש:
const link = buildDayOffDeepLink(
  'https://yomsheni-il.monday.com/custom_objects/18417140187',
  1234567890,
);
// → https://yomsheni-il.monday.com/custom_objects/18417140187?app%5BitemId%5D=1234567890
```

> הערה על קידוד: `URL.searchParams`
> יקודד את הסוגריים כ-`%5B` / `%5D`.
> זה תקין לחלוטין —
> monday
> מפענחת אותם חזרה. אפשר גם לבנות את המחרוזת ידנית עם סוגריים רגילים (`app[itemId]`); שתי הצורות עובדות.

### בנייה ידנית של המחרוזת (חלופה)

```ts
const link = `${baseUrl}?app[itemId]=${encodeURIComponent(String(itemId))}`;
```

## 4. מה קורה כשלוחצים על הקישור

1. הקישור פותח את
   monday,
   ו-monday
   טוענת את אפליקציית
   Day-off
   בתוך ה-iframe (עם הסשן וההרשאות של המשתמש המחובר).
2. האפליקציה קוראת את
   `itemId`,
   מאתרת את הבקשה, ועוברת לטאב "ההיעדרויות שלי".
3. נפתחת תיבת הפרטים של אותו יום היעדרות — **בדיוק** כמו לחיצה על יום בלוח-השנה:
   - אם הבקשה ניתנת לעריכה (בקשה של המשתמש בסטטוס "ממתין לאישור") — יוצגו כפתורי **עריכת הבקשה** ו**ביטול הבקשה**.
   - אחרת (מאושר / נדחה) — תוצג תצוגה לקריאה בלבד עם כפתור **סגירה**.

הבקשה תיפתח גם אם היא משנה אחרת מזו שמוצגת כעת בלוח (האפליקציה מבצעת שליפה נקודתית של הפריט לפי המזהה).

## 5. דרישות ומגבלות

- **חייבים סשן monday.** הקישור עובד רק כשהוא נפתח בתוך
  monday
  (משתמש מחובר). פתיחת כתובת ה-GitHub Pages הגולמית בטאב דפדפן עצמאי לא תעבוד — אין שם סשן/הרשאות.
- ה-`itemId`
  חייב להצביע על **בקשה אישית** בלוח ההיעדרויות המוגדר באפליקציה. מזהה של "יום חברה" כללי, פריט מלוח אחר, או פריט שנמחק — לא יפתח כלום (ללא שגיאה למשתמש).
- ה-`baseUrl`
  משתנה לפי מופע ה-Day-off (ראו ההערה בסעיף 1). אפליקציית-המקור מחזיקה את הכתובת הרלוונטית למופע — אין להטמיע כתובת קבועה בקוד. בתוך אותו מופע, רק ה-`itemId`
  משתנה בין בקשה לבקשה.

```
לינק = baseUrl + "?app[itemId]=" + itemId
```

`itemId`
ו-`baseUrl`,
ולשרשר אותם בפורמט הזה.

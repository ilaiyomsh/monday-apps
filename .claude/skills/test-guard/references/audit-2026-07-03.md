# Mutation Audit — 2026-07-03 (baseline)

First full mutation audit of the agent-written test suites, run before the `test-guard`
skill existed — this file is both the empirical baseline and the open fix backlog.
Method: 3 parallel agents, one per project; 3 semantic mutations per module, applied one
at a time with `.mutbak` backup/restore; kill = at least one test fails. All baselines
were green before and after; all trees verified clean.

## What worked (keep doing this)

Tests written against a **named, real regression** killed their mutations every time:

- `vacationService` D8 regression tests killed both the silent-`pending` fallback and the
  `Number('') === 0` label-id trap.
- `useAllocations` futureClobber suite killed the merge→set clobber and the past-window
  shrink.
- `SettingsDialogShell` change-#74 tests killed both `setField` regressions (deps + spread
  order).
- `DEFAULT_SETTINGS` suite killed all 3 default-value mutations.

Conclusion baked into SKILL.md: tests born from an observed failure work; tests written
"to have tests" assert weakly. Hence the red gate.

## Survivors — the fix backlog (19)

Fixing a survivor = strengthen/add the assertion or fixture, then re-apply the same
mutation and watch it die (see `mutation-protocol.md`).

### Axis/Day-off (8)

1. `src/services/columnMap.ts` — `parseDateText` returns untrimmed text. No fixture with
   surrounding whitespace; a padded `' 2026-06-03 '` from monday text leaks as a malformed
   day-key.
2. `src/domain/dates.ts` — `relDays` `Math.round`→`Math.floor`. The test named
   "stable across DST-style boundaries" spans Jun 3→Jul 3 2026, which contains no DST
   transition — the rounding guard is never stressed.
3. `src/domain/absence.ts` — `reqWorkdayKeysInYear` year-clip `<`→`<=`. No fixture ends
   exactly on Jan 1 of the queried year.
4. `src/services/vacationService.ts` — `mapRequest` `submittedAt` no longer derived from
   `created_at`. Fixtures set `created_at`, but no test asserts `submittedAt` at all.
5. `src/domain/settingsValidation.ts` — wrong-type branch stops emitting aggregate
   `errors.columns` (the settings tab dot). Tests assert only `isValid` + per-field error.
6. `src/components/Settings/personalTypeDiff.ts` — `samePersonalTypeOptions` drops the
   color comparison. Test is named "compares element-wise by id/title/color/index" but no
   fixture pair differs by color (or title, or index) alone.
7. `src/components/ui/MonthCalendar.tsx` — `layoutWeek` continuation flags swapped. Test
   asserts only that SOME bar has `.cont-start` and SOME has `.cont-end`.
8. `../Services/axis-app-core/src/settings/SettingsDialogShell.tsx` — `handleSave` drops
   the `if (ok)` guard; dialog closes on failed save and loses the draft. Day-off tests
   only exercise `setField`; app-core's own suite has only `axiomTransport.test.ts`.

### Axis/Planner (9)

1. `src/hooks/useAvailability.ts` — missing-FTE default `?? 0`→`?? 100`. The employee
   factory always injects `allocationPercentage`, so the production fallback is never
   observed.
2. `src/hooks/useAllocations.ts` — history exhausted after 1 empty window instead of 2
   (Rule-2 gap-year protection). Every mocked past window is non-empty; the empty-window
   branch never executes in tests.
3. `src/hooks/useMondaySettings.ts` — `isConfigured` AND→OR. Only all-or-nothing fixtures;
   a half-configured install would skip the welcome/settings gate.
4. `src/hooks/useMondaySettings.ts` — `saveSettings` drops `previous_version` (optimistic
   concurrency). Storage mock ignores the options argument; the "preservation" test file
   never invokes the hook.
5. `src/hooks/useProjectCosts.ts` — `formatCost` fraction digits 0→2. All assertions are
   substrings/prefixes, never an exact string. **Side finding: the hook body itself is
   dead code — no production file imports it.**
6. `src/hooks/useSettingsValidation.ts` — work-hours boundary `>=`→`>`. No fixture with
   equal or inverted hours; the generic validation surface has zero direct coverage
   (only the Day-off-oriented test file exists).
7. `src/utils/dateUtils.ts` — `formatDateRange` same-month collapse ignores the year.
   Same-year fixtures only; "12 Jun 2025 – 15 Jun 2026" would collapse wrongly.
8. `src/utils/workDaysUtils.ts` — `isLoadCountedDay` personal day-off guard removed. The
   module's test file never imports the function; its consumers (`useCompanyLoad`,
   `useEmployeeLoad`) have no tests at all.
9. `src/utils/projectClassification.ts` — classification precedence swapped. Fixtures use
   disjoint internal/external sets, so ID-first bucket order is unobservable.
